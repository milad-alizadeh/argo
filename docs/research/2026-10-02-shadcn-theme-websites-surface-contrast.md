# Shadcn theme galleries and surface contrast

**Checked:** 2026-10-02
**Question:** Which ready-made shadcn theme sites are useful to browse, and does any published theme clearly separate Argo's four native surfaces in both Light and Dark?

## Useful sites to browse

These are direct theme tools, galleries, or official documentation—not roundup articles. Shadcnblocks and the tweakcn Theme Picker are the best places here to browse already-published palettes. The other tools help inspect or shape a theme, but mostly generate a custom result rather than offer a curated set of named schemes.

## Surface-role audit

I inspected the published CSS or registry values for the named themes below. Surface tuple order is **background / card / popover / sidebar**. OKLCH lightness values make exact equality and very small differences easier to spot, but do not by themselves establish usable contrast. The OKLab ΔE column measures the distance between the four adjacent pairs in that order; values around 0–2 are barely separated, while larger values are more apparent. Chroma and hue are included in those distances. This is a source-payload color-distance check, not a screenshot of Argo or a claim that different CSS strings create useful surfaces.

The Shadcnblocks entries are directly served as `registry:theme` JSON and contain paired `light` and `dark` values. For example, the Vercel entry has a Light background at `oklch(0.99 0 0)` and card at `oklch(1 0 0)`, then Dark card `oklch(0.14 0 0)` and popover/sidebar `oklch(0.18 0 0)`. Amber Minimal has identical Light background/card/popover at `oklch(1 0 0)`. These source values verify the role equality without relying on the theme names or marketing descriptions.

### Foreground checks

Check each theme's `--foreground` against the four surface roles and check each action token against its own foreground counterpart (`--primary` / `--primary-foreground`, and `--destructive` / `--destructive-foreground`). For example, Catppuccin uses `oklch(0.44 0.04 279.33)` for Light surface text and pairs white with its Light primary `oklch(0.55 0.25 297.02)`; Ocean Breeze pairs white with its Light primary `oklch(0.72 0.19 149.58)`. These are the actual exported pairs, not a guarantee of WCAG AA. Validate the chosen pairs with a browser-based contrast checker before making any accessibility claim; no ratios are reported here.

## Recommendation for Argo

**No inspected ready-made theme clearly separates both background/card and sidebar/background in both modes.** Several options improve one mode: Ocean Breeze, Vercel, Amber Minimal, and Modern Minimal have a noticeable Dark background/card split but almost none in Light; Claymorphism has that split in Light but none in Dark. Catppuccin provides restrained background/card and sidebar/background differences across modes, with a strong popover distinction, but its Dark background/card pair is nearly the same color. Card and popover sharing a value is not itself a blocker when the main layers separate. None of these candidates is a direct fix for the requested two-mode surface hierarchy; do not derive new values or add aliases to make one pass.

Keep the mapping to the four existing native roles: outer/native background → `--background`, feed card → `--card`, sidebar → `--sidebar`, floating panel → `--popover`. Leave Theme independent from Mode. Each palette must retain both mode blocks, and System should follow the OS without changing the selected palette. Import color declarations only; skip fonts, radius, shadows, spacing, component code, and base styles so Argo's typography, geometry, and existing shadcn bindings remain intact.

Before adopting any candidate, check the rendered session list and status treatments in both modes. The theme exports inspected here do not define Argo-specific warning/danger/status roles. Keep their foreground pairs with their own surfaces, and separately check primary/destructive control pairs.
