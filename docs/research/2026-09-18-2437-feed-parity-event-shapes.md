# Feed parity event shapes for #2437

Date: 2026-09-18

Scope: the event shapes that Argo currently observes for Claude Code and Codex, and how those shapes become Feed rows and Roster text. This note maps the observed subset. It does not claim to describe the full upstream Claude Code or Codex protocols.

## Source base

The shared adapter boundary is `SessionSource`. It gives the shared reader transcript discovery, a transcript-chain read, optional live overlays, optional shell output, optional delegation transcripts, optional delegation usage, managed rows, locks, rename, and optional index capabilities. See `apps/desktop/src/domains/sessions/main/session-source.ts:30`.

The shared normalized transcript model is `TranscriptRecord`. Messages can carry prose, thought, marker, event, tool, image, file, and source blocks. Tool calls have `{ id, name, input }`. Tool results have `{ callId, blocks, failed, background? }`. Non-message records include delegation, command output, title, skill body, trace, plan, compaction, setup, usage, turn, background task, and unreadable records. See `apps/desktop/src/domains/sessions/contract/transcript.ts:4`, `apps/desktop/src/domains/sessions/contract/transcript.ts:17`, `apps/desktop/src/domains/sessions/contract/transcript.ts:21`, and `apps/desktop/src/domains/sessions/contract/transcript.ts:78`.

The Feed row contract has tool kinds `command`, `read`, `edited`, `created`, `tool`, `skill`, and `searched`; delegation rows; marker rows; event rows; command-output rows; and ask rows. See `apps/desktop/src/domains/sessions/contract/feed-rows.ts:23`, `apps/desktop/src/domains/sessions/contract/feed-rows.ts:62`, `apps/desktop/src/domains/sessions/contract/feed-rows.ts:96`, and `apps/desktop/src/domains/sessions/contract/feed-rows.ts:151`.

Feed projection reads each normalized record in `rowsOfRecord`. It turns compaction records into `marker: compacted`, aborted turns into `marker: interrupted`, command-output records into command-output rows, event records into event rows, delegation records into delegation rows, and message blocks into prose, thought, tool, marker, event, image, source, and prompt attachment rows. It drops sidechain messages from a parent Feed. See `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:28`, `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:34`, `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:43`, `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:54`, `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:56`, `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:58`, `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:71`, and `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:95`.

Roster projection reads the same transcript chain. `projectRosterRow` derives title, status, place, started time, activity, plan, delegations, shell commands, pull request, usage, context window, and setup from transcript records. See `apps/desktop/src/domains/sessions/main/roster.ts:140`.

## Shared tool and text derivation

`tool-feed.ts` is the shared tool-text catalogue. It classifies Claude `Bash`, `Edit`, `Read`, `Write`, and `Skill`; Codex `exec_command`, `exec`, `web__run`, and `apply_patch`; and falls back to `kind: "tool"` plus `Ran <name>` or the tool input title. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:40` and `apps/desktop/src/domains/sessions/contract/tool-feed.ts:96`.

Tool evidence is also shared. Claude `Bash` and `Read` route to output and document evidence, file edits route to diff evidence, and unknown tools route to output when they have a result. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:73` and `apps/desktop/src/domains/sessions/contract/tool-feed.ts:117`.

Tool row text is shared. Claude `Bash`, Codex `exec_command`, Codex `exec`, Claude `Skill`, and Codex `web__run` get inline text. Known evidence-routed tools get no inline text. Unknown tools show `code`, a lone string argument, or JSON input. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:135` and `apps/desktop/src/domains/sessions/contract/tool-feed.ts:105`.

Tool grouping is shared. Each kind owns an icon, route, verb, noun, and group wording. Unknown tools and web searches both fold into the command count for group labels. See `apps/desktop/src/domains/sessions/contract/tool-groups.ts:24`, `apps/desktop/src/domains/sessions/contract/tool-groups.ts:56`, and `apps/desktop/src/domains/sessions/contract/tool-groups.ts:79`.

Roster activity uses `toolPresentation(call)` too, then adds `tool` and `target` fields. It finds targets from path fields and text fields. See `apps/desktop/src/domains/sessions/contract/signals.ts:121` and `apps/desktop/src/domains/sessions/contract/signals.ts:133`.

Roster shell commands do not use the shared command classification. They use one raw tool name: `Bash`. See `apps/desktop/src/domains/sessions/contract/signals.ts:12` and `apps/desktop/src/domains/sessions/contract/signals.ts:73`.

The renderer consumes these derived rows. `FEED_ROW_RENDERERS` draws each Feed row shape. Tool rows and groups go to `FeedToolLine` and `FeedToolGroup`. Roster rows pass the derived session into `SessionRosterItem`. See `apps/desktop/src/domains/sessions/renderer/feed/feed-row-renderers.tsx:66`, `apps/desktop/src/domains/sessions/renderer/feed/feed-tools.tsx:52`, `apps/desktop/src/domains/sessions/renderer/feed/feed-tools.tsx:119`, and `apps/desktop/src/domains/sessions/renderer/components/roster/roster-row-view.tsx:63`.

## Semantic equivalences

Tool calls are already normalized. Claude `tool_use` blocks and Codex `function_call` or nested `custom_tool_call` entries both become shared `ToolCall` records. Tool results from both adapters become shared `ToolResult` records keyed by call id. See `apps/desktop/src/agents/claude/sessions/block-reader.ts:56`, `apps/desktop/src/agents/claude/sessions/block-reader.ts:90`, `apps/desktop/src/agents/codex/sessions/tool-calls.ts:64`, and `apps/desktop/src/agents/codex/sessions/tool-calls.ts:120`.

Command Feed rows are equivalent at the reader-facing level. Claude `Bash`, Codex `exec_command`, and Codex `exec` all map to Feed kind `command` and show inline command text when present. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:42`, `apps/desktop/src/domains/sessions/contract/tool-feed.ts:53`, and `apps/desktop/src/domains/sessions/contract/tool-feed.ts:135`.

File edit Feed rows are equivalent at the row level. Claude `Edit` and `Write`, plus Codex nested `apply_patch`, become `edited` or `created` rows with diff evidence and line counts. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:46`, `apps/desktop/src/domains/sessions/contract/tool-feed.ts:65`, and `apps/desktop/src/domains/sessions/contract/tool-changes.ts:20`.

Delegations are equivalent at the shared row level. Claude `Task`/`Agent` and task notifications, Codex `SubAgentActivity`, and both adapters' realtime delegation envelopes all become `delegation` records. Roster delegation text reads only those records, keyed by `groupId`. See `apps/desktop/src/agents/claude/sessions/spawned-agents.ts:66`, `apps/desktop/src/agents/claude/sessions/task-notification.ts:46`, `apps/desktop/src/agents/codex/sessions/subagent-activity.ts:14`, `apps/desktop/src/agents/codex/sessions/harness-envelopes.ts:52`, and `apps/desktop/src/domains/sessions/contract/signals.ts:43`.

Compaction has equivalent settled Feed output. Claude `compact_boundary` and Codex `compacted` records both become `compaction` records, and those become a Feed compacted marker. See `apps/desktop/src/agents/claude/sessions/records.ts:119`, `apps/desktop/src/agents/codex/sessions/records.ts:147`, and `apps/desktop/src/domains/sessions/main/feed-row-projection.ts:34`.

Message callbacks are equivalent only as live overlays. Claude `MessageDisplay` batches and Codex JSON-RPC agent-message deltas both become live assistant prose rows, and settled transcript messages later replace or supersede the draft. See `apps/desktop/src/agents/claude/drive/live-messages.ts:20`, `apps/desktop/src/agents/codex/drive/live-messages.ts:21`, `apps/desktop/src/agents/claude/sessions/read-sessions.ts:141`, and `apps/desktop/src/agents/codex/sessions/read-sessions.ts:47`.

Plans are equivalent only after projection. Claude can write incremental plan changes with `TaskCreate` and `TaskUpdate`; Codex writes a whole plan snapshot with `update_plan`. Both feed `readPlan`, but the source semantics differ. See `apps/desktop/src/agents/claude/sessions/plan-changes.ts:1`, `apps/desktop/src/agents/codex/sessions/plan-changes.ts:1`, and `apps/desktop/src/domains/sessions/main/roster.ts:162`.

## Gaps and inconsistencies

Roster shell activity is Claude-only. Feed classifies Codex `exec_command` and `exec` as commands, and Roster activity can show them as the current activity. The shell list uses only raw `Bash`, and `SessionSource.readShellOutput` is documented as absent for every CLI but Claude today. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:53`, `apps/desktop/src/domains/sessions/contract/signals.ts:12`, and `apps/desktop/src/domains/sessions/main/session-source.ts:38`.

Web search is Codex-only in the typed Feed catalogue. Codex nested `web__run` becomes `searched`. Claude web tools such as `WebFetch` are permission-gated in the driver, but the Feed catalogue has no Claude web mapping, so a transcript tool with that name falls back to `kind: "tool"`. See `apps/desktop/src/agents/claude/drive/permission-gate.ts:148`, `apps/desktop/src/domains/sessions/contract/tool-feed.ts:40`, `apps/desktop/src/domains/sessions/contract/tool-feed.ts:62`, and `apps/desktop/src/domains/sessions/contract/tool-feed.ts:96`.

Questions differ in durability. Claude `AskUserQuestion` is a persisted tool call/result pair, so the question and answer can be read from the transcript. Codex `requestUserInput` is held as a live pending question and has no persisted transcript row to replace. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:161`, `apps/desktop/src/agents/codex/sessions/read-sessions.ts:30`, and `apps/desktop/src/agents/codex/sessions/read-sessions.ts:62`.

Delegation provenance differs. Claude creates a delegation record from the spawning tool call itself, even before a task notification arrives. Codex collaboration calls are hidden, so the visible delegation depends on `SubAgentActivity` or realtime envelopes. See `apps/desktop/src/agents/claude/sessions/spawned-agents.ts:25`, `apps/desktop/src/agents/codex/sessions/tool-calls.ts:90`, and `apps/desktop/src/agents/codex/sessions/subagent-activity.ts:14`.

Compaction live state differs. Claude needs a `PreCompact` hook file because it writes no transcript while compaction is in progress. Codex managed sessions can read `contextCompaction` item lifecycle callbacks. The settled Feed marker still converges. See `apps/desktop/src/agents/claude/compaction/compaction-hook.ts:1`, `apps/desktop/src/agents/claude/compaction/compaction-roster.ts:19`, and `apps/desktop/src/agents/codex/drive/compact-protocol.ts:9`.

Codex nested tool parsing is intentionally partial. It reads `tools.<name>(...)` from JavaScript source outside strings and comments, extracts quoted `cmd`, `q`, `url`, `ref_id`, and `apply_patch` patch arguments, and pads missing nested results. A tool call shape outside that subset can still fall back to a generic `exec` row. See `apps/desktop/src/agents/codex/sessions/nested-tool-call.ts:3`, `apps/desktop/src/agents/codex/sessions/tool-calls.ts:44`, `apps/desktop/src/agents/codex/sessions/tool-calls.ts:64`, and `apps/desktop/src/agents/codex/sessions/nested-results.ts:1`.

File-edit fidelity differs. Claude `Edit` and `Write` carry structured old/new/content fields. Codex gets structured diff rows only for nested `apply_patch`; file changes made inside a shell command remain command text and output. See `apps/desktop/src/domains/sessions/contract/tool-changes.ts:20`, `apps/desktop/src/agents/codex/sessions/tool-calls.ts:80`, and `apps/desktop/src/domains/sessions/contract/tool-feed.ts:135`.

Thread discovery differs. Claude subagent transcripts are side files joined by a meta file that names the spawning tool id. Codex subagent transcripts are normal rollout files that are hidden from the main Roster and reopened by matching parent metadata or direct delegation id files. See `apps/desktop/src/agents/claude/sessions/subagents.ts:1`, `apps/desktop/src/agents/codex/sessions/discover.ts:47`, and `apps/desktop/src/agents/codex/sessions/discover.ts:126`.

Pull request marks are Claude-only today. Roster reads `pull-request` records generically, but the comment in `roster.ts` says only a Claude transcript carries that record today. See `apps/desktop/src/domains/sessions/main/roster.ts:94`.

## Where duplication lives

The main duplicate is tool presentation. `tool-feed.ts` maps raw CLI tool names to reader-facing labels, kinds, text, and evidence. `signals.ts` uses `toolPresentation` for activity but separately hard-codes shell command detection to `Bash`. `tool-groups.ts` separately owns the kind-level icon, route, verb, noun, and grouping grammar. See `apps/desktop/src/domains/sessions/contract/tool-feed.ts:40`, `apps/desktop/src/domains/sessions/contract/signals.ts:12`, `apps/desktop/src/domains/sessions/contract/signals.ts:133`, and `apps/desktop/src/domains/sessions/contract/tool-groups.ts:24`.

The second duplicate is live message overlay logic. Claude and Codex both build `{ id, text }` live messages and both use an adapter-owned `overlayFor`, but the callback shapes, retirement rules, and draft id rules live in each adapter. See `apps/desktop/src/agents/claude/drive/live-messages.ts:20`, `apps/desktop/src/agents/codex/drive/live-messages.ts:21`, `apps/desktop/src/agents/claude/sessions/live-feed.ts:17`, and `apps/desktop/src/agents/codex/sessions/read-sessions.ts:47`.

The third duplicate is delegation-thread recovery. Both adapters expose `readDelegationFiles`, but Claude joins from sidecar meta files while Codex first tries parent metadata and then a direct `<delegationId>.jsonl` fallback. See `apps/desktop/src/agents/claude/sessions/read-sessions.ts:134`, `apps/desktop/src/agents/codex/sessions/read-sessions.ts:140`, `apps/desktop/src/agents/claude/sessions/subagents.ts:22`, and `apps/desktop/src/agents/codex/sessions/discover.ts:129`.

## Most useful follow-up shape

The next parity change wants one adapter-owned "observed action" projection before the shared Feed and Roster text. It would let each adapter classify raw events into shared action kinds: command, shell command, read, edit, create, search, skill, ask, delegation, plan, compaction, message draft, and thread status. The shared layer would then stop naming `Bash`, `exec`, `web__run`, and `apply_patch`, and Roster shell activity would not have to rediscover command semantics from raw tool names.
