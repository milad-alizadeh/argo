# Desktop shadcn component provenance audit

2026-10-01. Scope: every production `.ts` or `.tsx` source in `apps/desktop/src/platform/renderer/components/ui/` at main revision `bd7d2860cc3deab17097893f25d74bbbf5f7b55a`. I read the same directory in the research worktree and verified `git diff bd7d2860cc3deab17097893f25d74bbbf5f7b55a HEAD -- apps/desktop/src/platform/renderer/components/ui` is empty. This is an audit, not an instruction to overwrite files. The directory has **58 production sources** and one story (`dropdown-trigger.stories.tsx`); it has no tests. The [local configuration](../../apps/desktop/components.json) selects `base-nova`, `cssVariables: true`, the Phosphor icon library, and `components/ui` as the `ui` alias. The [official base source tree](https://github.com/shadcn-ui/ui/tree/main/apps/v4/registry/bases/base/ui) contains counterparts by name for 56 of the 57 production `.tsx` files. `dropdown-trigger.tsx` is not in that tree. `use-mobile.ts` is an [official hook source](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/bases/base/hooks/use-mobile.ts), although Argo stores it inside `ui/`.

## What provenance means here

The official authored Base UI files are **not** byte-for-byte installable `base-nova` files. The [registry build script](https://github.com/shadcn-ui/ui/blob/main/apps/v4/scripts/build-registry.mts) transforms authored source and style tokens into selected-style files and public registry JSON. On 2026-10-01 at `19:34:13 UTC`, an approved read-only network fetch returned HTTP 200 for **all 56** `https://ui.shadcn.com/r/styles/base-nova/<name>.json` items corresponding to local `.tsx` registry candidates. The installed `shadcn@4.21.0` CLI then produced each selected, Phosphor-transformed file through `add <name> --view <name>.tsx -c <app>` and a read-only `--diff`; the separate `use-mobile` JSON also returned HTTP 200. Raw payload SHA-256 hashes are recorded below. The endpoint is mutable, so this is a verified **fetch-time baseline**, not a pinned upstream commit. [shadcn CLI](https://ui.shadcn.com/docs/cli), [registry build script](https://github.com/shadcn-ui/ui/blob/main/apps/v4/scripts/build-registry.mts).

Comparison method: parse local and CLI-transformed TSX with Babel's TypeScript/JSX parser, then compare named top-level declarations as syntax trees after removing source positions, comments, and formatting. Import path rewriting, import order, and export order are reported separately from component-body drift. A second pass ignores only `strokeWidth={2}` to identify icon-only additions. This is stronger than a text diff but not a complete runtime proof: CSS values outside this directory and dependency versions can still change rendering. Codes in the inventory: **K** = component bodies match the fetched baseline; **B** = restore a baseline-only difference with no app-specific adaptation identified; **R** = restore selected registry source and extract a named app appearance/behavior; **M** = move an app-owned module outside `ui/`; **H** = official helper whose body matches but whose location should follow the hooks alias. All 56 registry candidates have a fetch-time comparison, so no `K` is based on filename alone. Every line reference below is to `apps/desktop/src/platform/renderer/components/ui/<file>`; exports are exact public names from current source. A **policy violation** means product roles or behavior are embedded in `ui/` under Argo's proposed pristine-boundary rule, independent of why the edit was originally made.

## Confirmed boundary cases

- **`badge.tsx` has product size/type and status choices in the registry boundary.** The fetched `base-nova` Badge has a fixed `h-5 px-2 py-0.5 text-xs` base and no size axis or warning variant. Local `compact` and both `text-badge` classes (`badge.tsx:9-12`) replace that size behavior; its added `warning` variant consumes `warn` (`badge.tsx:14-22`). This is a verified selected-payload difference and a pristine-boundary policy violation. The local `destructive` variant remains present; `warning` adds a distinct status. Restore the selected Badge baseline, then put compact sizing, `text-badge`, and warning/status appearance into an app-owned Badge recipe or composition with named variants. [Official Badge item](https://ui.shadcn.com/r/styles/base-nova/badge.json).
- **`combobox.tsx` adds trigger behavior inside a registry component.** The fetched `base-nova` `ComboboxInput` has no `triggerLabel` or trigger `tabIndex`. Local source accepts `triggerLabel = 'Show options'` and passes `aria-label` plus `tabIndex={-1}` to its trigger button (`combobox.tsx:45-71`). This is a verified behavior difference, not merely an uncertain class difference. Preserve the accessibility intent in an app-owned composition or named adapter, check keyboard behavior, and restore selected registry source. An explicit fork is warranted only if the official public pieces cannot express the required trigger behavior. [Official Combobox item](https://ui.shadcn.com/r/styles/base-nova/combobox.json).
- **`dropdown-trigger.tsx` is app-owned, not a shadcn primitive.** It exports `SearchableDropdownTrigger` and `MenuDropdownTrigger`, composes the app `Icon` with `Button` and two registry triggers, and adds the app's `size="control"` icon choice (`dropdown-trigger.tsx:3-6,14-54`). It has a colocated story. Move the component and story to an app-owned shared or domain location; leave `ui/` for installed registry source. No upstream same-name file appears in the [official base tree](https://github.com/shadcn-ui/ui/tree/main/apps/v4/registry/bases/base/ui).
- **`empty.tsx` embeds product typography and changes geometry.** The fetched `base-nova` item has `text-sm font-medium tracking-tight` for title, `text-sm/relaxed` for description, `text-sm` for content, `rounded-xl border-dashed` on the root, and `size-8` icon media. Local source uses `type-title`, `type-body`, omits those root classes, and enlarges icon media to `size-10` (`empty.tsx:8-10,30-35,57-85`). These are verified selected-payload differences. Restore baseline; put product typography and geometry in an app-owned Empty composition. Keep direct-default and adapted specimens. [Official Empty item](https://ui.shadcn.com/r/styles/base-nova/empty.json).
- **`command.tsx` adds an app-specific API and styling.** Fetched `base-nova` Command has a fixed input presentation. Local `CommandInput` adds `appearance: 'boxed' | 'inline'`, `type-control`, app `Icon`, and `inlineSearchGroupClassName` (`command.tsx:7-13,60-90`). Local `CommandItem` also changes selected background from `bg-muted` to `bg-accent` (`command.tsx:158`). The check indicator itself exists upstream; only the explicit stroke weight differs. Restore baseline; make an app-owned inline search composition and selected-state recipe. [Official Command item](https://ui.shadcn.com/r/styles/base-nova/command.json).
- **`input-group.tsx` exports a product recipe from vendor space.** The fetched item has no `inlineSearchGroupClassName`; the local exported search string (`input-group.tsx:11-12`) is used by Command. Move the recipe with its app owner and restore selected Input Group. Its stock `InputGroupButton` size variants otherwise match baseline. [Official Input Group item](https://ui.shadcn.com/r/styles/base-nova/input-group.json).
- **`toast.tsx` substitutes an app Loader for the registry loading icon.** Local `ToastIcon` imports `../loader/loader` and renders it for `type === 'loading'` (`toast.tsx:7,130-165`); the fetched Phosphor-transformed item uses `SpinnerIcon` with `animate-spin`. Restore baseline if acceptable. If app Loader is required and Toast exposes no suitable injection point, make an explicit app-owned Toast fork outside `ui/`, with the reason and payload hash recorded. Other Toast shapes match after icon attributes are separated. [Official Toast item](https://ui.shadcn.com/r/styles/base-nova/toast.json).
- **`use-mobile.ts` is an official registry helper, not an app module.** Its full parsed source matches the fetched helper item, which targets `registry/base-nova/hooks/use-mobile.ts` (`use-mobile.ts:1-19`). Its placement in `ui/` blurs the boundary; the configuration already has a hooks alias. Place the pristine helper under hooks and update Sidebar's import when changing the installation layout. This is a location issue, not modified logic. [Official use-mobile item](https://ui.shadcn.com/r/styles/base-nova/use-mobile.json).

`sidebar.tsx` deserves separate product-fit review: the fetched source already contains its cookie, `Ctrl/Meta+B` listener, and responsive hook (`sidebar.tsx:23-27,51-107`), so those are **not** local drift. The local-only difference in its component body is `strokeWidth={2}` on `SidebarIcon` (`sidebar.tsx:262`). Restore that small visual difference for a pristine baseline, then decide whether the registry Sidebar's state/shortcut contract fits Argo without rewriting its internals. [Official Sidebar item](https://ui.shadcn.com/r/styles/base-nova/sidebar.json).

The product-token sweep across all 58 production files found `type-*` in Empty and Command, `text-badge` and `warn` in Badge, and no `danger`, `active`, or named shell/navigation/session spacing token use in production `ui/` source. `--drawer-*`, `--sidebar-*`, `--radius-md`, and semantic shadcn color roles come from the fetched registry source where used; they are not app adaptations. The one colocated story uses `--size-session-menu`, but it is excluded from production inventory and should move with `dropdown-trigger`. The local `bubble.tsx:21-35` `color-mix()` and relative `oklch()` expressions match the fetched selected-style Bubble body, as do its seven variants. They are **vendor defaults**, not Argo drift. Under a pristine-source policy, preserve that source and assess any desired product-specific bubble appearance in the app layer. [Official Bubble item](https://ui.shadcn.com/r/styles/base-nova/bubble.json).

Other verified style/behavior differences deserve explicit extraction or restoration: Button `sm` uses local `text-xs` versus fetched `text-[0.8rem]` (`button.tsx:25`); Alert Dialog, Card, Dialog, Drawer, Questionnaire, and Sheet titles add local `font-heading` (`alert-dialog.tsx:102`, `card.tsx:40`, `dialog.tsx:109`, `drawer.tsx:180`, `questionnaire.tsx:59`, `sheet.tsx:97`); Skeleton changes `bg-muted` to `bg-muted-foreground/15` (`skeleton.tsx:9`); Attachment targets `[data-slot=loader]` where fetched source targets spinner (`attachment.tsx:50`); Dialog adds `overlayClassName` (`dialog.tsx:41-55`). `alert.tsx` adds `min-w-0` to title/description (`alert.tsx:41,54`) and `input.tsx` changes only the prop type signature (`input.tsx:5`) relative to fetched source. These are source differences, not inferred intent. [Official Button item](https://ui.shadcn.com/r/styles/base-nova/button.json), [official Alert item](https://ui.shadcn.com/r/styles/base-nova/alert.json), [official Input item](https://ui.shadcn.com/r/styles/base-nova/input.json).

## Anti-drift convention and update proof

shadcn's [introduction](https://ui.shadcn.com/docs) deliberately gives projects ownership of copied code and allows direct edits. Argo's desired **pristine `ui/` boundary** is stricter local policy. It should be explicit: no app `type-*` role, product variant, domain import, app-owned recipe, or custom behavior in registry files; no wrapper is required where a direct registry import fits. Semantic theme color values may change through the central CSS contract while registry source, default numeric type/size classes, and structure stay fixed. An app-specific appearance belongs in a named app composition; an unavoidable fork is named, located outside `ui/`, and tracked against a recorded upstream payload. [shadcn theming](https://ui.shadcn.com/docs/theming), [shadcn components.json](https://ui.shadcn.com/docs/components-json).

For updates, the current [official CLI](https://ui.shadcn.com/docs/cli) documents `add --dry-run`, `--view`, `--diff`, `--cwd`, and `--overwrite`. Use the installed app CLI, not an unreviewed `@latest`. A read-only review can inspect the selected item with `add <item> --view -c <app>`, `--diff`, or `--dry-run`; `--overwrite` is a write and must not be a discovery step. A fetched built-in registry item is mutable even with a pinned CLI. Record the selected style/base, CLI version, fetch date, exact registry payload or hash/upstream commit, dependency list, and file targets. The official [GitHub registry guide](https://ui.shadcn.com/docs/registry/github) recommends a full commit SHA for reproducible GitHub registry references; that guarantee does not transfer to a bare built-in item name.

Review three separate claims: **source identity** (the selected, transformed source comparison plus recorded payload hash), **default contract** (global CSS has not remapped upstream numeric utilities such as `text-xs`/`text-sm`), and **rendered appearance** (direct default and adapted component in light/dark, with computed type, spacing, focus, and interaction checks). A zero CLI diff alone does not prove all three. This audit settles the fetched source comparison for all 56 registry candidates and the helper; it does not settle the CSS or render claims. Compare fetched files to a clean candidate outside the live tree; name each intentional app extraction and verify consumers before any selected-file update. Do not blanket-overwrite `ui/`. [shadcn CLI](https://ui.shadcn.com/docs/cli), [Tailwind theme namespaces](https://tailwindcss.com/docs/theme), [local typography test](../../apps/desktop/src/platform/renderer/styles/typography-contract.test.ts#L24).
