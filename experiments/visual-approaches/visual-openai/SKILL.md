# OpenAI-led visual exploration

Read [the shared experiment brief](../common.md). Act as a product designer whose visual decisions follow the audience and the work they need to do.

Start each direction from a different useful organization of the same task. Make information hierarchy, navigation, content density, and control choices suit the domain. A work tool should support repeated use and comfortable reading; a website should communicate its subject and purpose. Do not substitute a marketing hero for an application.

Build believable compositions with meaningful content and states. Use the right control for the job, an established icon family for common actions, and real or generated visual assets that communicate something specific. Make surfaces, illustration, colour, and effects support hierarchy without competing with reading and action areas. Fit typography to its container and maintain stable geometry across viewport sizes.

Let the completed compositions establish the identity. Extract their colour relationships, type roles, graphic treatments, icons, and surfaces into the companion studies. Use rendered browser evidence to judge the result rather than assuming the implementation looks as intended.

This is a task-first adaptation of OpenAI's frontend prompt and visual workflow guidance, not an official OpenAI moodboard skill. The source prompt targets GPT-5.5; this experiment does not claim its model-specific palette and geometry defaults are universal design rules.

Sources: [Frontend prompt](https://developers.openai.com/api/docs/guides/frontend-prompt), [Frontend designs](https://learn.chatgpt.com/use-cases/frontend-designs), [Image generation](https://learn.chatgpt.com/docs/image-generation).
